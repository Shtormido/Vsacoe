# HANDOFF — Нефритовое Го

Передаточная записка: что это за проект, как он устроен, как его запускать и проверять, что осталось сделать. Состояние на версию **2.0**, ветка `jade-go` репозитория `Shtormido/Vsacoe`.

## Что это

Игра го в браузере. В ней есть:
- 3D-стол в семи местах и 2D-доска, доски 9, 13, 19 и 21;
- бот четырёх уровней (поиск Монте-Карло, считает в Web Worker);
- 12 уроков, задачи дня и бесконечная тренировка задач (генератор с решателем);
- свои камни из картинок игрока;
- звук, рассчитанный физически (модальный синтез), и генеративная музыка;
- онлайн-партии на двоих через свой сервер, аккаунты и рейтинг;
- игра гостем без регистрации, зрители, архив открытых партий и повторы любых партий.

Весь клиент — один HTML-файл без сборки. Сервер написан только на стандартной библиотеке Python 3. Работает на Kali Linux (как служба systemd) и на Windows 10/11.

## Структура

```
site/index.html          весь клиент (≈2700 строк: HTML, CSS, JS в одном файле)
site/login.html          страница входа для закрытого сервера (--private)
site/vendor/             three.js r128, OrbitControls, шрифты Prata и Golos Text (OFL) — игра работает без интернета
server/serve.py          HTTP-сервер: статика, gzip, кэш, CSP, /api/*, Server-Sent Events, проверка входа
server/netgo.py          онлайн-комнаты: правила го на сервере, часы, подсчёт, реванш, чат
server/accounts.py       аккаунты: SQLite, хеши паролей, сессии, Эло, история, админские команды
deploy/install.sh        установка службы systemd на Kali/Debian (/opt/jade-go, пользователь jadego)
deploy/nginx-jade-go.conf  вариант с nginx и HTTPS: /api/ проксируется в serve.py без буферизации
start-windows.bat        запуск на Windows двойным щелчком
data/                    база аккаунтов при локальном запуске (в .gitignore)
README.md                инструкция для пользователя (на русском)
```

## Запуск

```bash
python3 server/serve.py                       # http://0.0.0.0:8080, регистрация открыта
python3 server/serve.py --signup invite       # регистрация только по приглашениям; closed — только админ
python3 server/serve.py --private             # без входа открывается только login.html
python3 server/serve.py --guests off          # по сети только с аккаунтом (пишется в базу)
sudo ./deploy/install.sh [--port 80] [--signup invite] [--private]   # служба на Kali
```

- Переменные окружения дублируют параметры: `JADEGO_HOST`, `JADEGO_PORT`, `JADEGO_DIR`, `JADEGO_DATA`, `JADEGO_SIGNUP`, `JADEGO_PRIVATE`, `JADEGO_GUESTS`.
- Разрешены ли гости, хранится в таблице `settings`, а не в параметрах. `--guests` и `install.sh --guests` только записывают значение, администратор потом меняет его в окне «Аккаунт» или командой `accounts.py guests on|off`.
- `site/index.html` можно открыть и как файл (`file://`). Тогда библиотеки грузятся с CDN, а онлайн-игра и аккаунты скрыты.

## Клиент: `site/index.html`

Всё лежит внутри одного IIFE в строгом режиме и разбито на разделы `/* ---------- … ---------- */`. По порядку:

| Раздел | Что внутри |
|---|---|
| utils & procedural textures | шум, все текстуры рисуются на canvas: дерево, камни, листва, облака, вода, кои… |
| data | `SETS` (камни), `TONES` (резонансы камней), `ENVS` (7 мест), `BOARDS` (5 досок) |
| settings | `ACTIONS`/`DEFKEYS` (горячие клавиши по `e.code`), `DEF`, объект `S` в `localStorage['jadego.settings']` |
| engine | `engineFactory()`: правила, MCTS, оценка мёртвых камней, подсчёт, задачи (`E.pz`). Тот же код запускается в двух Worker: `AI` (бот) и `PZW` (составляет задачи) |
| audio | `AU`: модальный синтез стука, фоновые звуки мест, генеративная музыка (Karplus-Strong, сякухати, пэды) |
| game state | объект `G` — вся текущая партия |
| 3D view | `create3D()`: сцена three.js, доски, `buildGarden/Tearoom/Club/Night/Onsen/Autumn/Sea`, режим «Созерцание» |
| 2D view | `create2D()`: canvas-доска |
| game flow | ходы, пас, бот, ход назад, подсчёт, конец партии, сохранение (`jadego.game`) |
| accounts | `AUTH`, окно «Аккаунт» |
| online play | `NET`, `netState`/`netApply`/`netRebuild`, чат, комнаты |
| statistics | локальная статистика (`jadego.stats`), выгрузка SGF |
| replays | `RP`, `startReplay`, `rpGo`/`rpPlay`, `endViewing`: повтор партии из статистики, аккаунта или архива |
| main menu and changelog | `APP_VER`, `NEWS` («Что нового»), `openMain` |
| tutorial & daily puzzles | `LESSONS`, `PUZZLES` (13 ручных, запасные для задач дня), тренировка: `loadTraining`, `pzJudge`, `pzHint` |
| menus / boot | привязка кнопок и окон, `boot()` |

Ключевые соглашения:
- **Режим партии** задаёт `G.level`: `0..3` — бот, `-1` — вдвоём на одном устройстве (`hot()`), `-2` — по сети (`net()`), `-3` — повтор (`replay()`, `G.phase==='replay'`).
- **Зритель** — это `net()` с `NET.watch=true` (`watching()`): поток `/watch`, в состоянии `you=0`, чата нет, `jadego.net` не трогается. `endViewing()` выходит из повтора или просмотра и вызывается из `openMain()`; свою идущую онлайн-партию ради просмотра или повтора бросить нельзя (`busyOnline()`).
- **Повтор** заранее считает все позиции (`RP.pos`), поэтому шаг назад и ползунок срабатывают мгновенно. Шаг вперёд анимируется через `view().onCommit`.
- **Онлайн**:
  - сервер присылает полное состояние комнаты, клиент сверяет его со своим `G.moves`;
  - если пришёл ровно один новый ход соперника, клиент его анимирует;
  - пока свой ход ещё не подтверждён (`NET.pending`), устаревшие состояния без него пропускаются;
  - во всех остальных случаях `netRebuild()` переигрывает партию с нуля;
  - если сервер отклонил ход, клиент заново применяет последнее состояние.
- **Новое место**:
  - добавить запись в `ENVS`;
  - написать `buildXxx()` и подключить его в `buildEnv()`;
  - нарисовать превью `.th-xxx` в CSS;
  - добавить фон для 2D в `setEnv()` и звуки в `AU.applyEnv()`.
- **Новая версия**: увеличить `APP_VER` и добавить запись в начало `NEWS`.
- **Курс** (`CHAPTERS`, `LESSONS`): шаги бывают `info`, `ok` (верные пункты `1`), `seq` (ходы с ответами белых `a`, `b`), `goal` (`cap`/`save`/`kill`/`live` — судит решатель через `lessonGoal` → `pzJudge`), `gen` (задача из генератора), `tap` (отметить мёртвые `d`/`D`, фаза `scoring`), `quiz` (вопрос с вариантами), `okFn`. Прогресс — множество id в `localStorage['jadego.course']`, урок засчитывается, когда решён его последний шаг. Каждое изменение курса проверяется прогоном всех шагов через движок и судью (позиции, допустимость, решение до конца, отказ неверному ходу).
- **Качество графики** (`GFX`, `Q(a,b)`): `S.gfx` = auto/low/mid/high/ultra задаёт сглаживание, плотность пикселей, тени и сколько листвы, частиц и разрешения текстур рисует сцена; меняется перезагрузкой.
- **«Только фон»** (`calm`, `setCalm`, `poke`): на стартовых экранах через минуту без ввода (или по кнопке-глазу `#mmEye`) окна становятся прозрачными; первое касание или клавиша только возвращают меню и никуда не нажимают.
- 2D-холст пишет свою сетку в `#c2d[data-grid]` (`N,gx,gy,cell`) — по ней тесты щёлкают в пункты.
- **Заставка** (`ATT`, `attractStart`/`attractStep`/`attractStop`): пока ничего не идёт (`G.phase` idle или законченная локальная партия), `G.level=-4` (`demo()`), бот уровня «Любитель» играет сам с собой прямо в главном потоке (`ENG.genMove`), `body.attract` прячет плашки и панель, камера идёт по пути «созерцания» (`V3D.setZen(true,true)`), на широком экране сдвинута вправо (`setShift`), на телефоне — вверх. Любой запуск партии меняет `G.level` и `G.token` — цикл и летящий камень останавливаются сами.
- **Закрытие окон**: `closeTop()` — одно место для Esc, крестика (`sheetChrome()` добавляет `.sx` в каждую карточку), касания по фону и кнопки «Назад» телефона (`popstate` → `onBack`, одна запись истории `{jg:1}` на открытое окно).
- **Запуск страницы**: `boot()` ждёт `netPing` и `authLoad` (не дольше 2,5 с). Без входа на сервере открывается `openWelcome()` — окно аккаунта на вкладке регистрации; после входа или «Позже» — главное меню. Ссылки `?room=` и `?watch=` это окно пропускают.
- **Задачи** (`E.pz` в движке, доска 9×9):
  - `reader(t,att,budget)` — тактическое чтение: `attack` (ход нападающего, который захватит цепочку за d своих ходов), `defend`, `reply` (самый упорный ответ). Кандидаты: дыхания, вторые дыхания, спасение и захват цепочек в контакте; защитник может и пропустить ход.
  - `ld(eye,w,def,budget)` — жизнь и смерть: полный перебор внутри пространства глаз, итог 1 жива / 0 мертва / −1 не дочитано; жизнь проверяется алгоритмом Бенсона (`benson`).
  - `make(kind,tier,seed)` — детерминированный генератор (`cap`, `save`, `kill`, `live`, сложность 0–2). Задача принимается, только если верный первый ход один, соперник спасся бы, ходи он первым, и чтение уложилось в бюджет. Позиция поворачивается одной из 8 симметрий.
  - Номер задачи в тренировке — это seed; тема «Все» чередует виды по номеру. Недавние позиции (с учётом поворотов, `pzCanon`) пропускаются. Прогресс — `localStorage['jadego.pz']`.
  - На странице ходы судит `pzJudge` теми же решателями: неверный ход откатывается, белые отвечают самым упорным ходом; жизнь и смерть считается решённой, когда итог не меняется, даже если белые сходят дважды подряд.
- **Свои камни**: набор `SETS.custom` с `type:'img'`. Картинки лежат в `localStorage['jadego.stones']` (квадрат 256×256, PNG), `loadCustom()` раскладывает их в пиксели, а `stoneTex` проецирует картинку на сферу сверху. Такие камни не поворачиваются случайно (`stoneYaw`).
- **Стиль кода** плотный, в одну строку, как в исходном файле. Комментарии английские, интерфейс русский. Имена из сети вставляются только через `textContent` или `esc()`.

## Сервер

### API (`/api/…`, JSON)

| Метод и путь | Назначение |
|---|---|
| `GET ping` | сервер доступен |
| `GET auth/me` | текущий пользователь, режим регистрации, закрытый ли сервер |
| `POST auth/register` / `auth/login` / `auth/logout` | вход и выход, cookie `jg_session` |
| `POST auth/password` / `auth/name` | смена пароля (завершает остальные входы) и имени |
| `GET admin/overview` · `users?q=&offset=` · `games?q=&offset=` · `invites` · `rooms` | только админ: сводка, настройки и журнал; поиск игроков и партий; приглашения; все комнаты |
| `POST admin/user` | `{id, action}`: `login`, `name`, `password`, `rating{rating,games,wins}`, `role`, `block{on}`, `logout`, `clear_games`, `delete` — с записью в журнал; себя нельзя заблокировать или удалить, последнего админа — разжаловать |
| `POST admin/games` · `admin/invites` · `admin/rooms` · `admin/settings` | удалить партии (`ids` / `clear_all`), `recompute`; создать или удалить код; закрыть комнату; `{guests, signup, motd}` |
| `POST auth/rename` | `{login, password}`: новый логин, подтверждённый паролем; попытки ограничены как вход |
| `GET people?q=` · `people/<login>` | поиск игроков по логину или имени (без запроса — кто заходил последним); страница игрока: рейтинг, «в сети» (заходил ≤ 5 мин назад), «играет сейчас» с кодом комнаты, если партию можно смотреть, открытые партии. Доступно и гостям |
| `GET friends` · `POST friends/add` · `friends/remove` | только с аккаунтом: друзья, входящие и отправленные заявки; `{login}` — заявка (или принять встречную) и удалить друга / отклонить / отменить. `auth/me` возвращает `friendReq` — число входящих заявок |
| `POST auth/hide` | `{hide}`: скрыть все свои партии (и живые комнаты сразу) |
| `POST auth/server` | только админ: `{guests}` — разрешить или запретить гостей |
| `GET me/games` · `GET leaderboard` | история своих онлайн-партий (с `id` для повтора), лучшие игроки |
| `GET live` | открытые идущие партии для списка «Идут сейчас» |
| `GET games` · `GET games/ID` | архив открытых партий; одна партия с ходами (открытая или своя) |
| `POST rooms` | создать комнату: `{n, komi, color, clock, watch}`, гостю ещё `name` → `{code, token, color}` |
| `GET rooms/CODE` | сведения о комнате, в том числе `public` и `watchers` |
| `POST rooms/CODE/join` | войти: `{watch}`, гостю ещё `name`. Тот же аккаунт получает своё прежнее место |
| `POST rooms/CODE/act` | `{token, type}`: `move{p}`, `pass`, `resign`, `undo_req`, `undo_ans{ok}`, `dead{points}`, `agree{ver}`, `resume`, `chat{text}`, `watch{on}`, `rematch`, `leave` |
| `GET rooms/CODE/events?token=` | поток SSE: при каждом изменении приходит полное состояние комнаты |
| `GET rooms/CODE/watch` | поток SSE для зрителя: то же состояние с `you=0` и без чата; `event: hidden`, когда партию скрыли |

### Внутреннее устройство
- **Комнаты** (`netgo.py`) хранятся в памяти под одним `RLock`.
  - Сервер сам проверяет ходы, очерёдность и часы (бёёми 3 × 30 с); поток `_ticker` фиксирует просрочку времени.
  - Брошенные комнаты удаляются по таймаутам: неначатые через 6 часов, брошенные партии через сутки.
  - Когда партия кончилась, вызывается `ON_FINISH(room, result, public)`: запись партии и пересчёт Эло (только если оба игрока с аккаунтами).
  - У каждого места есть `want` (переключатель игрока) и `hide` (настройка аккаунта). Партия открыта (`Room.public()`), только если оба места заняты и у обоих `want and not hide`. При каждой рассылке закрытой комнаты зрители отключаются.
  - Зрители — подписки с цветом `0`. Сами по себе они комнату не держат: по таймауту её удаляют и при живых зрителях.
- **Аккаунты** (`accounts.py`) лежат в SQLite в режиме WAL: таблицы `users`, `sessions` (хранятся только sha256 токенов), `games`, `invites`, `settings`, `audit` (журнал администраторов, последние 2000 записей), `friends` (строка `a → b`, `ok=0` пока заявка без ответа; удаляется вместе с аккаунтом).
  - Режим регистрации, гости и объявление (`motd`) — в `settings`; `--signup`/`--guests` при запуске только записывают туда значение. Заблокированный (`users.blocked`) не входит, его сессии не действуют.
  - `recompute()` строит рейтинг заново: всем 1500, затем все рейтинговые партии по порядку окончания.
  - Новые столбцы добавляет `MIGRATIONS` при запуске: `users.hide_games`, `games.public`, `games.started`, `games.clock`. Старые партии остаются закрытыми.
  - Гость в `games` — это `black`/`white` = NULL. Архив показывает партии с `public=1`, если ни у одного игрока не включено `hide_games`.
  - Пароли — PBKDF2-SHA256, 240 000 итераций.
  - Вход ограничен: 10 ошибок за 10 минут по IP и по логину.
  - Первый зарегистрированный становится админом.
- **Безопасность** (`serve.py`):
  - CSP разрешает inline-скрипты и `blob:`-воркер бота;
  - POST с чужим `Origin` отклоняется;
  - содержимое папок не показывается, скрытые файлы не отдаются;
  - лимит тела запроса 8 КБ;
  - за nginx адрес игрока берётся из `X-Forwarded-For`.

## Как проверялось

Автотестов в репозитории **нет**. Проверка была такая:
- игра открывалась в headless Chromium через Playwright (WebGL на SwiftShader, Chromium лежит в `/opt/pw-browsers`);
- сценарии: все 7 мест и 5 досок, партия в 2D и 3D, меню, настройки, клавиши, часы, фора, статистика, SGF;
- сервер: запросы к API, закрытый режим, вход и регистрация, интернет заблокирован (игра работает только с локальными файлами);
- онлайн: два отдельных браузера играют друг с другом — регистрация, комната, ходы, чат, просьба вернуть ход, перезагрузка страницы посреди партии, подсчёт, реванш, рейтинг;
- звук: записывался реальный аудиовыход страницы и разбирался по спектрограммам и уровням.

Сами скрипты были временными и в репозиторий не попали. Версию 2.0 проверяли в Node: по 25 задач каждого вида и уровня решены до конца по подсказкам через `pzJudge`, неверные первые ходы отклоняются; в 150 номерах тактика не повторяется, жизнь и смерть повторяется в 25–40 % (поэтому `pzCanon`). В браузере — тренировка, задачи дня, партия 21×21 в 2D и 3D, загрузка своих картинок. Версию 1.9 проверяли так же:
- API: гость без имени, гость против аккаунта, зритель, скрытие посреди партии, архив, «скрыть все», отключение гостей, рейтинговая партия, обновление базы 1.8;
- три браузера: гость, аккаунт и зритель. Проверены список «Идут сейчас», выход зрителя при скрытии, повтор из архива, статистики и аккаунта, ширина телефона.

**Хороший следующий шаг** — перенести их в `tests/` и запускать одной командой.

## Известные ограничения

- Онлайн-комнаты живут в памяти: после перезапуска сервера идущие партии пропадают. История и рейтинг сохраняются, они в SQLite.
- Блокировка входа по логину позволяет на 10 минут закрыть вход чужому аккаунту, если подбирать ему пароль.
- Зрители не пишут в чат, а игроки не видят, кто именно смотрит, — только число зрителей.
- Имя гостя может совпасть с именем игрока с аккаунтом. Гость везде помечен словом «гость».
- Гостей ограничивает только общий лимит: не больше 30 комнат в час с одного IP.
- Служба systemd и `start-windows.bat` на настоящих Kali и Windows не запускались, только в Linux-контейнере (установщик прогонялся вхолостую).
- На слабых телефонах скорость 3D не замерялась. Количество листвы и частиц уже уменьшено (`isCoarse`).
- Звук и музыка проверены анализом записи, а не на слух.

## Идеи на будущее

- Автотесты в `tests/`, чтобы гонять их перед каждым изменением.
- Хранить онлайн-комнаты в SQLite, чтобы партии переживали перезапуск сервера.
- Лобби: открытые комнаты, которые ждут соперника.
- Бот как соперник в онлайн-комнате; анализ сыгранной партии.
- Сохранять настройки и статистику в аккаунте, а не только в браузере.
