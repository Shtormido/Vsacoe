# HANDOFF — Нефритовое Го

Передаточная записка: что это за проект, как он устроен, как его запускать и проверять, что осталось сделать. Состояние на версию **1.8**, ветка `jade-go` репозитория `Shtormido/Vsacoe`.

## Что это

Игра го в браузере. В ней есть:
- 3D-стол в семи местах и 2D-доска;
- бот четырёх уровней (поиск Монте-Карло, считает в Web Worker);
- 12 уроков и ежедневные задачи;
- звук, рассчитанный физически (модальный синтез), и генеративная музыка;
- онлайн-партии на двоих через свой сервер, аккаунты и рейтинг.

Весь клиент — один HTML-файл без сборки. Сервер написан только на стандартной библиотеке Python 3. Работает на Kali Linux (как служба systemd) и на Windows 10/11.

## Структура

```
site/index.html          весь клиент (≈2700 строк: HTML, CSS, JS в одном файле)
site/login.html          страница входа для закрытого сервера (--private)
site/vendor/             three.js r128, OrbitControls, шрифты Prata и Golos Text (OFL) — игра работает без интернета
server/serve.py          HTTP-сервер: статика, gzip, кэш, CSP, /api/*, Server-Sent Events, проверка входа
server/netgo.py          онлайн-комнаты: правила го на сервере, часы, подсчёт, реванш, чат
server/accounts.py       аккаунты: SQLite, хеши паролей, сессии, Эло, история, админские команды
deploy/install.sh        установка службы systemd на Kali/Debian (/opt/jade-go, пользователь jadego)
deploy/nginx-jade-go.conf  вариант с nginx и HTTPS: /api/ проксируется в serve.py без буферизации
start-windows.bat        запуск на Windows двойным щелчком
data/                    база аккаунтов при локальном запуске (в .gitignore)
README.md                инструкция для пользователя (на русском)
```

## Запуск

```bash
python3 server/serve.py                       # http://0.0.0.0:8080, регистрация открыта
python3 server/serve.py --signup invite       # регистрация только по приглашениям; closed — только админ
python3 server/serve.py --private             # без входа открывается только login.html
sudo ./deploy/install.sh [--port 80] [--signup invite] [--private]   # служба на Kali
```

- Переменные окружения дублируют параметры: `JADEGO_HOST`, `JADEGO_PORT`, `JADEGO_DIR`, `JADEGO_DATA`, `JADEGO_SIGNUP`, `JADEGO_PRIVATE`.
- `site/index.html` можно открыть и как файл (`file://`). Тогда библиотеки грузятся с CDN, а онлайн-игра и аккаунты скрыты.

## Клиент: `site/index.html`

Всё лежит внутри одного IIFE в строгом режиме и разбито на разделы `/* ---------- … ---------- */`. По порядку:

| Раздел | Что внутри |
|---|---|
| utils & procedural textures | шум, все текстуры рисуются на canvas: дерево, камни, листва, облака, вода, кои… |
| data | `SETS` (камни), `TONES` (резонансы камней), `ENVS` (7 мест), `BOARDS` (5 досок) |
| settings | `ACTIONS`/`DEFKEYS` (горячие клавиши по `e.code`), `DEF`, объект `S` в `localStorage['jadego.settings']` |
| engine | `engineFactory()`: правила, MCTS, оценка мёртвых камней, подсчёт. Тот же код запускается в Worker (`AI`) |
| audio | `AU`: модальный синтез стука, фоновые звуки мест, генеративная музыка (Karplus-Strong, сякухати, пэды) |
| game state | объект `G` — вся текущая партия |
| 3D view | `create3D()`: сцена three.js, доски, `buildGarden/Tearoom/Club/Night/Onsen/Autumn/Sea`, режим «Созерцание» |
| 2D view | `create2D()`: canvas-доска |
| game flow | ходы, пас, бот, ход назад, подсчёт, конец партии, сохранение (`jadego.game`) |
| accounts | `AUTH`, окно «Аккаунт» |
| online play | `NET`, `netState`/`netApply`/`netRebuild`, чат, комнаты |
| statistics | локальная статистика (`jadego.stats`), выгрузка SGF |
| main menu and changelog | `APP_VER`, `NEWS` («Что нового»), `openMain` |
| tutorial & daily puzzles | `LESSONS`, `PUZZLES` |
| menus / boot | привязка кнопок и окон, `boot()` |

Ключевые соглашения:
- **Режим партии** задаёт `G.level`: `0..3` — бот, `-1` — вдвоём на одном устройстве (`hot()`), `-2` — по сети (`net()`).
- **Онлайн**:
  - сервер присылает полное состояние комнаты, клиент сверяет его со своим `G.moves`;
  - если пришёл ровно один новый ход соперника, клиент его анимирует;
  - пока свой ход ещё не подтверждён (`NET.pending`), устаревшие состояния без него пропускаются;
  - во всех остальных случаях `netRebuild()` переигрывает партию с нуля;
  - если сервер отклонил ход, клиент заново применяет последнее состояние.
- **Новое место**:
  - добавить запись в `ENVS`;
  - написать `buildXxx()` и подключить его в `buildEnv()`;
  - нарисовать превью `.th-xxx` в CSS;
  - добавить фон для 2D в `setEnv()` и звуки в `AU.applyEnv()`.
- **Новая версия**: увеличить `APP_VER` и добавить запись в начало `NEWS`.
- **Стиль кода** плотный, в одну строку, как в исходном файле. Комментарии английские, интерфейс русский. Имена из сети вставляются только через `textContent` или `esc()`.

## Сервер

### API (`/api/…`, JSON)

| Метод и путь | Назначение |
|---|---|
| `GET ping` | сервер доступен |
| `GET auth/me` | текущий пользователь, режим регистрации, закрытый ли сервер |
| `POST auth/register` / `auth/login` / `auth/logout` | вход и выход, cookie `jg_session` |
| `POST auth/password` / `auth/name` | смена пароля (завершает остальные входы) и имени |
| `GET me/games` · `GET leaderboard` | история своих онлайн-партий, лучшие игроки |
| `POST rooms` | создать комнату (нужен вход): `{n, komi, color, clock}` → `{code, token, color}` |
| `GET rooms/CODE` | сведения о комнате |
| `POST rooms/CODE/join` | войти. Тот же аккаунт получает своё прежнее место |
| `POST rooms/CODE/act` | `{token, type}`: `move{p}`, `pass`, `resign`, `undo_req`, `undo_ans{ok}`, `dead{points}`, `agree{ver}`, `resume`, `chat{text}`, `rematch`, `leave` |
| `GET rooms/CODE/events?token=` | поток SSE: при каждом изменении приходит полное состояние комнаты |

### Внутреннее устройство
- **Комнаты** (`netgo.py`) хранятся в памяти под одним `RLock`.
  - Сервер сам проверяет ходы, очерёдность и часы (бёёми 3 × 30 с); поток `_ticker` фиксирует просрочку времени.
  - Брошенные комнаты удаляются по таймаутам: неначатые через 6 часов, брошенные партии через сутки.
  - Когда партия кончилась, вызывается `ON_FINISH`: запись партии и пересчёт Эло.
- **Аккаунты** (`accounts.py`) лежат в SQLite в режиме WAL: таблицы `users`, `sessions` (хранятся только sha256 токенов), `games`, `invites`.
  - Пароли — PBKDF2-SHA256, 240 000 итераций.
  - Вход ограничен: 10 ошибок за 10 минут по IP и по логину.
  - Первый зарегистрированный становится админом.
- **Безопасность** (`serve.py`):
  - CSP разрешает inline-скрипты и `blob:`-воркер бота;
  - POST с чужим `Origin` отклоняется;
  - содержимое папок не показывается, скрытые файлы не отдаются;
  - лимит тела запроса 8 КБ;
  - за nginx адрес игрока берётся из `X-Forwarded-For`.

## Как проверялось

Автотестов в репозитории **нет**. Проверка была такая:
- игра открывалась в headless Chromium через Playwright (WebGL на SwiftShader, Chromium лежит в `/opt/pw-browsers`);
- сценарии: все 7 мест и 5 досок, партия в 2D и 3D, меню, настройки, клавиши, часы, фора, статистика, SGF;
- сервер: запросы к API, закрытый режим, вход и регистрация, интернет заблокирован (игра работает только с локальными файлами);
- онлайн: два отдельных браузера играют друг с другом — регистрация, комната, ходы, чат, просьба вернуть ход, перезагрузка страницы посреди партии, подсчёт, реванш, рейтинг;
- звук: записывался реальный аудиовыход страницы и разбирался по спектрограммам и уровням.

Сами скрипты были временными и в репозиторий не попали.

**Хороший следующий шаг** — перенести их в `tests/` и запускать одной командой.

## Известные ограничения

- Онлайн-комнаты живут в памяти: после перезапуска сервера идущие партии пропадают. История и рейтинг сохраняются, они в SQLite.
- Блокировка входа по логину позволяет на 10 минут закрыть вход чужому аккаунту, если подбирать ему пароль.
- Зрителей и списка открытых комнат нет: в комнату входят только два игрока по коду.
- Служба systemd и `start-windows.bat` на настоящих Kali и Windows не запускались, только в Linux-контейнере (установщик прогонялся вхолостую).
- На слабых телефонах скорость 3D не замерялась. Количество листвы и частиц уже уменьшено (`isCoarse`).
- Звук и музыка проверены анализом записи, а не на слух.
